# Mac App Implementation Plan (Plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The "Video Prompt" menu-bar app: record the Chrome window (or screen or area) with
mic narration and on-screen drawing, then review and Send / Save & copy / Copy reference /
Discard. Plus the Recordings window, retention, and the "Claude is waiting" dot, all on top
of Plan 1's core.

**Architecture:** Testable logic lives in a new `VPApp` library: settings, raw recorder,
window tracking, drawing model, recording state machine, menu, review, delivery and
recordings models. It talks to the system through small protocols (capture backend, window
source, pasteboard, clock), so tests use fakes. `VPCapture` wraps ScreenCaptureKit (display
stream + `SCRecordingOutput` with microphone). The `VideoPrompt` executable is a thin
AppKit/SwiftUI shell over those models. `scripts/build-app.sh` assembles and signs
`Video Prompt.app` with no Xcode (a spike showed a hand-built, ad-hoc-signed bundle gets its
own permission identity).

**Tech Stack:** Swift 6.3, SwiftPM, AppKit (`NSStatusItem`, `NSPanel`), SwiftUI (control bar,
review, Recordings), ScreenCaptureKit (`SCStream`, `SCRecordingOutput`, `captureMicrophone`),
CoreGraphics window list, Carbon `RegisterEventHotKey`, Plan 1's VPCore / VPProcess.

**Spec:** `docs/superpowers/specs/2026-10-06-video-prompt-design.md` (§2 decisions, §3.1–3.6
journey, §4 architecture, §5 capture, §7 storage contract, §8 security).
**Prototype (the look and flow to match):** https://claude.ai/artifact/4n5ZJ7ogjbBTDF1JrHGZbV

**Not in this plan (Plan 3):** first-run setup window, Developer ID signing and notarization,
Sparkle updates, bundled whisper-cli + model download, `.dmg` and cask, Open at login.

## Global Constraints

- **Floor raised to macOS 15** (`.macOS(.v15)` package-wide). Spec said 14+, but
  `SCRecordingOutput` and `SCStreamConfiguration.captureMicrophone` are 15+, and with them a
  segment is one ScreenCaptureKit call instead of a hand-synced AVAssetWriter plus a mic
  pipeline. Update spec §4 in Task 1.
- Bundle ID `ai.altitudeiq.videoprompt`; app name `Video Prompt.app`; `LSUIElement` true;
  `NSMicrophoneUsageDescription` = "Video Prompt records your narration so Claude can read
  what you said. Audio is transcribed on this Mac and never uploaded."
- Hardened runtime from day one, with entitlement `com.apple.security.device.audio-input`.
  No App Sandbox (the app runs `whisper-cli` and writes the shared data folder).
- No network calls, no listeners (spec §8). The app reads and writes only the Paths data root.
- Event coordinates: global screen points, origin **top-left** of the primary display (the
  raw-folder contract, spec §7). AppKit's bottom-left points convert at one place only
  (`ScreenGeometry`).
- Copy reference text: `@"<absolute path>/prompt.md"`. Double quotes are required: the data
  root has a space, and the quoted form was verified in Claude Code.
- Copy (verbatim): primary button `Send to waiting session` (a session is waiting) or
  `Save & copy reference` (none). Secondary `Copy reference`, then `Discard`. Menu header
  `Claude is waiting for a recording`. Soft warning at 3:00: `Long recordings give Claude many
  frames. Wrap up soon?` Control-bar caption `Hidden from the recording`.
- Defaults: mode `.window` (Chrome), drawings fade after 3 s, review step on, retention
  `.days(3)`, shortcut ⌃⌥⌘R.
- Run tests with `scripts/test.sh`. Build the app with `scripts/build-app.sh`.

## Review Focus

1. **Pause, then resume after the window moved**: events after resume must land in the new
   segment with segment-relative times (Task 3 `eventsAfterResumeUseNewSegment`).
2. **Chrome not running, or its window minimized, when recording starts**: the menu item
   disables with "Chrome isn't open"; minimized mid-recording logs `visible: false` (Task 4
   `noChromeMeansNoWindowItem`, `minimizedLogsHidden`).
3. **The waiting session quits while the review panel is open**: Send must re-check the
   waiter at click time. If it's gone, fall back to Save & copy and say so (Task 10
   `sendFallsBackWhenWaiterLeft`).
4. **App quits or crashes mid-processing**: at launch, `processing` recordings become
   `processingFailed` with Retry, and Retry re-runs the processor on the kept raw folder
   (Task 12 `strandedProcessingMarkedFailed`, `retryProcessesKeptRaw`).
5. **Draw toggled on, then Stop pressed**: the overlay must stop swallowing clicks
   immediately, or the user's screen is "frozen" (Task 7 `stopTurnsDrawingOff`).
